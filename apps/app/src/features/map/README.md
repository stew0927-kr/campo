# 지도 화면

기존 `useCampusData`, `useCampusRoute`, `useGpsMatcher`를 호출합니다. 계약·코어·실제 지도 파일은 수정하지 않습니다.

## 화면 구성 (전체화면 지도)

지도는 하단 탭 위까지 화면 전체를 채우고, 조작은 지도 위에 떠 있는 요소와 하단 시트로 나눕니다.

| 화면 | 위 | 아래(시트) |
|---|---|---|
| 기본 | 둥근 장소 검색바 + 파란 `길찾기` 버튼, `가장 가까운 화장실` 버튼, 개발 빌드에서는 `개발 데이터` 칩 | 데이터 상태 안내, 선택한 장소 카드(출발지로·도착지로·즐겨찾기), 실외/실내·건물·층, 이 보기의 장소 목록 |
| 출발·도착 입력 | 출발/도착 입력란, ↑↓ 바꾸기, ✕ 닫기(선택 초기화) | 이동 방식 5종, `길찾기` |
| 경로 결과 | 뒤로(입력 수정) + 출발→도착 요약 | `휠체어 가능` 스위치, 이동 방식 5종(누르면 즉시 재계산), 시간·거리·계단·층 이동, 왕복 보기, 위치 안내 시작/중지, `로드뷰로 보기`, 실내 층 보기, 단계별 안내(사진 있는 단계는 눌러서 지도 말풍선) |
| 지도에서 선택 | 없음(지도 전체 사용) | 안내 문구와 `지도 선택 취소` |

### 하단 시트

모든 화면의 시트는 핸들 줄을 위아래로 끌거나 누르거나, 오른쪽 `⌃`(크게 펼치기)·`⌄`(접기) 버튼으로 **펼침 / 기본 / 접힘** 세 상태를 오갑니다. 접힘에서는 핸들과 미니 바(경로 화면은 `12분 · 340m`)만 남고 지도가 화면을 채웁니다. 높이 계산은 `sheetModel.ts`(순수 함수)입니다.

### 가장 가까운 화장실

`가장 가까운 화장실` → 검색 화면에서 출발 위치를 `현재 위치` / `지도에서 선택` / 검색·건물 목록 중 하나로 고르면, `restroom.ts`가 코어 `findNearestRestroom`(지도 위 점은 `findNearestRestroomFrom`)으로 화장실을 정하고 기존 `useCampusRoute`로 경로를 바로 띄웁니다. `휠체어 가능`을 켜면 휠체어 사용 가능(`wheelchair: 'yes'`) 화장실만, `wheelchair` 방식으로 즉시 다시 찾습니다. 일반 길찾기에서도 같은 스위치가 `wheelchair` 방식을 켜고 끕니다.

### 계층 검색

검색어가 비어 있으면 건물(장소 많은 순, 마지막에 `야외 장소`) → 층 → 시설(화장실·강의실·출입구·기타) 순서로 내려가며 고릅니다(`placeTree.ts`). 검색어를 입력하면 기존처럼 평평한 결과 목록입니다.

### 캠퍼스 로드뷰

- 지도에서 초록 사진 지점(기본 화면) 또는 경로의 사진 단계(경로 화면, 같은 지점을 두 번 지나면 보라 점)를 누르면 썸네일 말풍선이 뜨고, 말풍선을 누르면 분할 로드뷰가 열립니다. 두 번 지나는 지점은 말풍선에서 `가는 길 · n단계` / `오는 길 · n단계`를 고릅니다.
- 분할 로드뷰(`RoadviewScreen.tsx`): 위 55%에 사진·진행 방향 화살표·이전/다음·`이 지점 다른 방향 사진`·전체화면 `↗↙`, 아래에 미니 지도(현재 지점 + 사진 `heading_deg`·`hfov_deg` 시야각 부채꼴, 다른 방향을 고르면 바로 회전)와 정보 카드(지점 이름, 실내/실외·층, 바라보는 방위, 단계 문구). Expo Go·웹은 미니 지도 대신 같은 부채꼴의 나침반을 그립니다.
- 사진 고르기·화살표는 기존 `photos/routePhotos.ts`·`viewerModel.ts`(코어 `choosePhotoForStep`·`photosForPoint`·`arrowFor`)를 그대로 쓰고, 장면·부채꼴·마커 묶음·왕복 잇기는 `photos/roadviewModel.ts`(순수 함수)입니다.
- 개발 메뉴 `실내·실외 로드뷰 시험`: `roadviewDemo.ts`의 가상 캠퍼스(정문·갈림길·광장 ↔ 가상 공학관 출입구 ↔ 1층 로비·계단·엘리베이터·화장실, 2층 복도·201호·화장실)와 지점별 2~4방향 SVG 가상 사진(`photos/demoPhotoArt.ts`, 네트워크 불필요)을 씁니다. 예시 버튼: 정문 → 201호, 왕복(정문 ↔ 본관 앞), 갈림길(정문 → 광장). 실제 한양대 길·사진이 아니며 data/·서버 사진과 섞지 않습니다.

- 우측 하단 `내 위치로 이동` 버튼은 누를 때만 위치 권한을 요청하고, 받은 좌표로 카메라를 옮기며 내 위치 점을 표시합니다.
- 입력란을 누르면 검색 화면이 열리고 `현재 위치`·`지도에서 선택`·검색 목록 중에서 고릅니다. 출발·도착이 모두 정해지면 바로 경로를 계산합니다. 다른 탭에서 넘어온 목적지는 기존처럼 사용자가 `길찾기`를 눌러 확인합니다.
- 검색바에서 고른 장소는 카메라를 그 위치로 옮기고(`MapProps.focus`), 하단 카드에서 출발지·도착지로 지정합니다.
- 안드로이드 뒤로가기: 로드뷰 → 지도 말풍선 → 검색 → 개발 메뉴 → 지도 선택 → 경로 결과 → 입력 화면 → 선택 장소 순서로 닫습니다.

- 검색, 지도 임의 점, 등록된 장소 점으로 출발·도착을 선택합니다. 지도 선택 모드에서 초록 점을 누르면 실제 노드로 선택합니다. 실내는 임의 좌표 대신 등록된 지점을 선택해야 합니다.
- 이동 방식 5종을 제공하고 내정보의 기본 보행 방식 변경을 반영합니다. 요청이 바뀌면 오래된 결과를 지웁니다.
- 실외 전체 경로 개요와 실내 건물·층 보기를 제공합니다. 실내 외곽선·연결은 등록된 데이터만 표시하며 층 번호로 경로를 만들지 않습니다.
- 앱 실행 중 장소 즐겨찾기를 공유합니다. 타 탭에서 온 목적지는 실제 노드 존재를 확인한 뒤 선택합니다. 없으면 이름 검색을 열며, 개발용 데이터와 실제 콘텐츠를 혼합하지 않습니다.
- 위치 권한은 사용자가 현재 위치 또는 위치 안내 시작을 눌렀을 때만 요청합니다. 권한이 없으면 수동 길찾기를 사용합니다. 위치 안내는 실외 경로 이탈 시 기존 엔진으로 재탐색하며, 실내는 정확한 지점을 수동 선택합니다. 백그라운드·탭 이탈·중지 시 센서 구독을 해제합니다. 기압계 실패 시 GPS만 사용합니다. 상대 높이만 전달하고 절대 기압·위치 이력을 저장하지 않습니다.
- 사진은 선택적인 `photoCatalog`(서버 공개 사진)가 제공될 때 기존 사진 Hook으로 고르고 로드뷰로 보여 줍니다. 가상 데이터에서는 로드뷰 시험 캠퍼스에만 가상 사진을 연결합니다.
- 실제 데이터는 현재 비어 있습니다. 개발 빌드에서 야외 가상 3지점 또는 기존 core `campus-basic` fixture를 복사한 실내 시험 번들을 선택할 수 있습니다. 실내 시험은 ‘정문 → 가상 408호 선택’ 후 길찾기를 누릅니다. 가상 지리·건물이며 실제 한양대 길이 아닙니다. 이 데이터로 장소 즐겨찾기는 만들지 않습니다.
- Expo Go/웹에서는 네이티브 지도 대신 안내 상자를 보여 줍니다. 웹용 추가 패키지는 설치하지 않았으므로 웹 실행 자체는 이번 환경에서 검증하지 않았습니다.

저장소 루트에서 기존 연결 테스트:

```sh
npx vitest run --config apps/app/src/features/map/vitest.config.mts
```

이 설정은 `model.test.ts`와 함께 `apps/app/test/appRoadview.test.ts`(가상 로드뷰 데이터·왕복/갈림길/실내 다방향 사진·마커 겹침·화장실·계층 검색·시트)와 `appMapScreen.test.ts`를 돌립니다. 둘은 루트 `npm test`에도 들어 있습니다.

새 지도·실내·센서·화면·탭 간 전달 테스트는 `apps/app/test/app*.test.ts`에 있고 루트 `npm test`에 포함됩니다. Node 화면 테스트는 네이티브 모듈을 대체한 렌더링 검사이며 실제 터치·지도·센서 E2E 검사가 아닙니다.

Android 개발 앱에서 확인할 것:

1. MapLibre 포함 개발 APK에서 첫 지도·OSM 타일·출처·확대·장소 선택을 확인합니다. 이번 작업에서는 APK를 만들거나 배포하지 않았습니다.
2. 작은 화면·큰 글씨·검색 키보드·모달 닫기를 확인합니다.
3. 위치 권한 거절 후 수동 경로와 다섯 이동 방식, 같은 출발·도착, 캠퍼스 밖 지점을 확인합니다.
4. 실내 시험 번들로 계단 회피·엘리베이터 우선·층 변경 표시를 확인합니다. 실제 데이터가 들어오면 현장 경로를 다시 확인해야 합니다.
5. 실외에서 위치 수신·이탈·재탐색·백그라운드·탭 이동·구독 중단을 확인합니다. 실내 GPS 층 추정은 별도의 현장 검증이 필요합니다.
6. 각 콘텐츠 탭과 즐겨찾기에서 지도 이동·자동 목적지 또는 검색 대체를 확인합니다.
