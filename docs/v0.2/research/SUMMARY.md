# v0.2 오픈소스 조사 요약

세 조사 노트를 합친 것이다. 상세 근거와 출처는 각 노트에 있다.

- [editor.md](editor.md) (A 편집기)
- [routing.md](routing.md) (B 길찾기)
- [pipeline.md](pipeline.md) (C 반자동 입력·제보)

`research-architecture.md` 1장의 사실은 설치된 버전에서 다시 확인했다. ngraph 5가지(ngraph.path 1.6.1), Terra Draw 1.39.0, Turf 7.4.0, Immer 11.2.10은 모두 그대로다. iD, OTP, Valhalla 부분은 지시대로 다시 열지 않았다.

이 문서는 제안만 담는다. SPEC은 고치지 않았다. 고칠지는 사람이 정한다.

## 2. 사람이 정해야 하는 것

노트는 제안만 적었다. 아래는 정해지기 전에는 SPEC에 쓸 수 없다.

1. `splitEdgeAt`에서 `step_count`가 0이 될 때 처리. 예: 최소 1로 올림, 나누기 거부.
2. 나눈 뒤 원래 id와 `rev`를 어느 쪽이 갖는지. iD는 더 긴 쪽이다.
3. `bridge`, `elevator` 구간을 나눌 수 있는지.
4. 같은 두 지점을 잇는 평행 구간을 함께 나눌지.
5. 새 id 생성 규칙(위 7번).
6. 계단 안내 문장을 합치는 규칙과 방향어 처리(위 3, 4번).

## 3. 그 밖의 발견 (SPEC 고침과 직접 관계없음)

- **문 → 복도선 자동 연결**: 실내 전용 도구는 없다. 가장 가까운 것은 GRASS `v.net connect -s`(GPL)와 JOSM "Join Node to Way"인데 둘 다 범용 기능이다. 따라서 6.1 `attachDoor`는 선행 구현이 없는 새 연산이다. 속성 테스트(D2)를 두껍게 하는 것을 권한다. 못 읽은 곳은 pipeline.md에 있다(Mapbox 문서, KDE 블로그 404 등).
- **maplibre-gl 6.17.0 `updateData`**: 지원한다. 조건은 모든 Feature에 고유 id가 있는 것이고, 현재 편집기는 이미 `id: f.id`를 넣어서 만족한다. 성능 이득은 WebGL로 재 보지 못했다. 추정이므로 측정 후 `setData`와 비교한다.
- **Rapid**: `beginTransaction/endTransaction`으로 이벤트를 모았다가 끝에 한 번 내는 구조가 있다. 매크로 하나가 동작 50개를 만들 때 쓸 만하다.
- **GraphHopper**: foot은 계단을 허용하되 3km/h로 느리게 잡고 벌점은 없다. 휠체어 파서는 9.0에서 삭제됐고 8.0 기준으로 계단을 막는다. 엘리베이터 처리는 확인하지 못했다.
- **iD 지도 위 오류 아이콘 방식**은 확인하지 못했다.
- **Immer 11.2.10**에 `enableArrayMethods`가 추가로 보인다. 용도는 읽지 않았다.

## 4. 라이선스 주의

## 5. 확인 수준에 대한 주의

- 노트 끝의 "캠포에 적용할 점"과 pipeline.md 5.2의 상태 표·묶기 설계는 조사 에이전트의 제안이다. 확인된 사실이 아니다.
- "묶음 상태가 전체에 적용된다"는 메일링 리스트 글을 검색 요약으로 본 2차 출처다.
- OTP에서 board와 hop이 문장을 만들지 않는다는 것은 추정이다(경로를 끝까지 읽지 않았다).
- 이 SUMMARY의 장·절 번호는 서브에이전트 보고에 적힌 것을 옮겼다. 저는 SPEC-v0.2.md를 이번에 직접 대조하지 않았다. SPEC을 고치기 전에 위치를 다시 맞춰 봐야 한다.
