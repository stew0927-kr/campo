# 실내·실외 지도 수정이 앱에 들어가는 길

앱(`apps/app`)은 **서버의 `campus_map_files`(Supabase, `supabase/migrations/0006_campus_maps.sql`)** 에서 지도를 받습니다.
서버 지도를 받기 전·받지 못했을 때만 앱에 들어 있는 지도(`assets/campus.generated.json`)를 씁니다.
그래서 **서버에 저장된 지도만 앱에 반영됩니다.**

## 저장하는 곳은 두 갈래

| 편집 화면 | 저장 위치 | 앱에 반영? |
|---|---|---|
| PC 편집기(`npm run editor`) | 이 PC의 `data/campuses/<id>/…` 파일 | **아니오.** 상태 막대에 노란 "이 PC에만 저장" 표시가 늘 보입니다. |
| 관리자 웹 → 매핑 탭(`/map/`, 서버 빌드) | 서버 `campus_map_files` (`save_campus_map`) | 예 |
| 관리자 웹 → 지도 파일 "폴더 올리기" | 서버 `campus_map_files` | 예 |

PC 편집기에서 고친 것을 앱에 넣으려면 그 폴더를 관리자 웹의 **폴더 올리기**로 올리거나, 처음부터 관리자 웹의 **매핑(/map/)** 에서 고쳐 저장합니다.

## 서버에 저장한 뒤 앱에 들어오기까지

1. 관리자 웹 매핑(/map/)에서 저장(또는 폴더 올리기) → `campus_map_files`의 그 파일 `updated_at`이 바뀝니다.
2. 앱은 다음 중 하나로 서버 지도를 **다시** 받습니다(앱을 다시 켤 필요 없음).
   - 지도 탭 시트 아래 **"지도 새로고침"** 버튼(`useCampusData().reload()` → `refreshCampusBundle()`).
   - 앱이 백그라운드에서 돌아왔을 때, 마지막으로 받은 지 **10분**(`CAMPUS_REFRESH_MS`)이 지났으면 자동으로(`useCampusAutoRefresh`).
   - 앱을 새로 켰을 때(처음 한 번).
3. 받는 동안에도 지금 지도는 그대로 보이고, 답이 오면 바뀝니다. 다시 받기에 실패(오프라인 등)하면 이미 받은 서버 지도를 그대로 둡니다.
4. 서버 지도는 **통째로** 씁니다. 건물 층(`buildings/*/L*.geojson`)·층 목록·3D 층·실내 선은 모두 서버 파일 기준이고,
   앱 번들과 파일 단위로 섞지 않습니다(서버 지도를 읽을 수 없을 때만 통째로 앱 번들).

## 확인 방법

- 서버: `campus_map_files`에서 고친 파일의 `updated_at`이 저장 시각으로 바뀌었는지 봅니다. 바뀌지 않았다면 서버에 저장되지 않은 것입니다(대개 PC 편집기에서 저장).
- 앱: 지도 탭 → 시트를 내려 **지도 새로고침** → 고친 건물·층을 열어 봅니다.
