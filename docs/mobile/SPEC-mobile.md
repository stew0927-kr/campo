# 캠포 현장 조사 앱 명세 (apps/mobile)

현장을 걸으며 한 손으로 지점·문·계단·출입구를 기록하고, 사진·기압·방향을 함께 남긴 뒤 PC 편집기에서 한 번에 불러오는 앱이다. 사용자용 길안내 앱이 아니다(SPEC-v0.2 9장의 "앱 화면"은 여전히 범위 밖).

## 1. 원칙

- **사진 경로와 센서값은 지도 원본에 넣지 않는다.** 현장 기록 파일에만 둔다. 지점의 개방시간·폐쇄기간·개방조건(`hours`, `closed_period`, `access_condition`)은 지도 원본의 선택 속성이라(SPEC.md 4.2) 앱이 `setProps`로 적고 changeset에 실린다.
- **앱도 `packages/core/src/edit`의 동작만으로 데이터를 바꾼다.** 편집기와 같은 엔진, 같은 불변식, 같은 되돌리기다.
- **위치는 앱 지도에서 사람이 직접 찍는다.** 화면 가운데 십자선 아래가 기록 위치다. 실내에서는 GPS를 쓰지 않는다.
- **앱 지도는 캠포 데이터(건물 외곽선, 지점, 구간)를 자체 캔버스에 그리고, 그 아래에 OpenStreetMap 타일을 깐다.** 타일은 `https://tile.openstreetmap.de/{z}/{x}/{y}.png`를 Web Mercator로 계산해 캠포 데이터와 같은 투영으로 놓는 그림일 뿐이다(`src/map/tiles.ts`). 타일을 받지 못하면(통신 없음) 그 타일만 빠지고 앱은 그대로 동작한다. 한 번 받은 타일은 기기 캐시 폴더(`expo-file-system`)에 저장해 다시 쓰고, 확대·축소로 줌이 바뀔 때는 직전에 다 그려진 줌의 타일을 새 타일이 올 때까지 아래에 깔아 둔다(깜빡임 없음). [설정]에서 현재 캠퍼스 범위의 타일(줌 15~18)을 미리 저장할 수 있다(`src/map/tileCache.ts`). 구글·네이버·카카오 지도는 들어가지 않는다(SPEC.md 3장). 화면에 `© OpenStreetMap 기여자`를 표시한다.
- 길찾기 규칙은 그대로다. 앱이 만드는 계단·엘리베이터·출입구 연결도 구간으로만 이어지고 층 번호를 비교하지 않는다.
- 현장에서 만든 Feature의 `source`는 `field-survey-{yyyy-mm}`이다(SPEC.md 4.1).

## 2. 기록 버튼

| 버튼 | 만드는 것 |
|---|---|
| 출발점 지정 | 십자선 근처의 기존 지점을 출발점으로 삼거나, 없으면 새 지점 |
| 갈림길 기록 | 지점 하나 + 직전 지점과 잇는 구간(바깥이면 `footway`, 건물 안이면 `corridor`) |
| 문/강의실 번호 | `door` 지점(`room_ref`) + 가까운 복도에 연결(`attachDoor`) |
| 계단/EV 층 변경 | 양쪽 층의 `stair_landing` 또는 `elevator_stop` + `steps` / `elevator` 구간. 출발과 도착에서 기압을 재어 높이를 남긴다 |
| 포탈 | `entrance` 지점 + 바깥 지점과 잇는 `edge_type: portal` 구간 |

문, 계단, 출입구를 기록할 때 [사진 촬영]으로 바로 찍을 수 있다. 화면 아래의 컴팩트한 도구 패널은 위 줄에 기록 버튼, 아래 줄에 도구(건물+OSM, 건물 그리기, 층 복사·연동, 사진·방향, 개방 정보, 옮기기, 되돌리기, 내보내기, 설정)를 두고, 건물·층 전환은 화면 위 칸이 맡는다. 터치 대상은 모두 38dp 이상이다(앱이 한 손·보행 중 지도를 넓게 쓰도록 이전의 56dp에서 줄였다).

### 2.1 기존 지점·문 정보 입력

십자선이 이미 있는 지점이나 문에 맞춰지면(2m 안, 초록 고리) 십자선 아래에 그 지점의 이름이 적힌 단추가 뜬다. 누르면 바텀 시트에서 개방시간·폐쇄기간·개방조건(빠른 선택 + 직접 입력), 메모, 사진을 적는다.

- 세 값은 지점 자체에 `setProps`로 적는다(되돌리기 한 번). 그래서 내보낸 `survey.json`의 changeset에 `modify`로 실리고, PC 편집기가 불러오면 그대로 반영된다.
- 같은 값과 메모·사진은 그 지점의 `attachments`에도 남는다(현장에서 본 기록).
- 걷던 자리(직전 지점)는 바뀌지 않는다.

### 2.2 건물 추가

등록되지 않은 건물은 앱에서 추가한다. 둘 다 동작 하나(되돌리기 한 번)이고, 만든 건물은 `needs_check`가 켜져 편집기에서 이어 검수한다.

- **건물+OSM**: 십자선이 건물 안쪽에 있을 때 누르면 앱에 실린 OSM 건물(`bundle-campus.mjs`가 `packages/editor/src/data/osm-campus/{campus}.json`을 함께 번들한다)에서 그 자리를 포함한 건물의 외곽선·이름·지상/지하 층수를 가져와 `addBuilding`으로 등록한다. 코드 `OSM{w|r}{id}`, `source: "osm"`. 이미 있는 건물 위나 OSM 건물이 없는 자리에서는 이유를 알려 준다. 등록되면 그 건물의 첫 지상층으로 이동해 바로 실내 기록을 이어 간다.
- **건물 그리기**: 모서리마다 십자선을 맞추고 [점 추가], 세 개 이상이면 [완료]로 이름과 층(`-1~4` 또는 `1,2,3`)을 적는다. 코드는 `N`+임의 6자이고 편집기에서 바꿀 수 있다.

### 2.3 층 복사·연동

현재 층의 지점(복도 지점, 계단참, 엘리베이터 정차 지점)과 평지 복도를 같은 좌표로 다른 층에 복사한다(`survey/floors.ts`). 편집기와 같은 `sync_group` 데이터를 쓰므로 내보낸 기록을 편집기가 그대로 연다.

- 원본과 복사본은 같은 `sync_group`(`sg_xxxxxx`)을 갖는다. 대상 층에 같은 종류의 지점이 1.5m 안에 있으면(엘리베이터 정차는 같은 `elevator_id`의 정차) 새로 만들지 않고 합류한다.
- 출입구와 층 사이 구간(계단·엘리베이터·에스컬레이터·연결통로·포탈)은 복사하지 않는다. 새로 만든 계단참·정차 지점에는 [계단/EV 층 변경]으로 구간을 이어야 한다고 알려 준다.
- 연동된 두 지점 사이에 갈림길 기록 등으로 평지 구간이 새로 생기면 연동된 다른 층의 두 지점 사이에도 같은 구간이 같은 동작 안에서 생긴다. [옮기기]로 연동된 지점을 옮기면 다른 층의 지점도 같은 좌표로 같이 옮겨진다.
- [층 복사·연동]에서 이 층 전체 또는 십자선 자리의 지점 하나를 연동 해제할 수 있다(`sync_group` 제거, 다른 층은 그대로).
- 전부 되돌리기 한 번이다.

### 2.4 사진 방향

사진마다 `heading_deg`(0~359°, 지도 북쪽 기준 시계 방향, 사진이 바라보는 방향)를 남긴다. 사진을 찍으면 나침반 값이 초기값으로 들어가고, 지점 중심에 고정된 원형 다이얼이 열린다. 손가락으로 다이얼을 돌려 부채꼴(시야 ±30°)을 맞추고(±1°/±5°, 반대쪽, 센서 값으로 버튼도 있다), 그 지점에서 뻗은 복도가 점선으로 그려져 실내 자기 오차를 눈으로 고칠 수 있다. 한 지점에 양방향 등 여러 장을 각각 다른 각도로 저장하고, [사진·방향]에서 저장된 사진의 방향을 다시 고칠 수 있다.

길찾기 쪽은 `packages/core`의 `pickPhotoByBearing(photos, bearing, tolerance=45)`로, 진행 방향각과 가장 가까운(허용 오차 안의) 사진을 고른다.

## 3. 센서

- **기압계**: 구간의 시작과 끝 기압 차이를 국제 기압고도식으로 높이(m)로 바꾼다(`heightFromPressure`). 짧은 시간의 차이만 쓰므로 날씨에 따른 절대 기압은 상쇄된다.
  - 계단/EV 층 변경은 출발과 도착에서 기압을 읽는다. 갈림길 기록은 직전 지점에서 읽은 기압(10분 안의 것)과 지금 기압을 쓴다. 이미 그려진 구간을 따라 걸어도 그 구간의 측정으로 남는다.
  - 경사도(%)는 평면 길이 5m 이상인 바깥 구간·포탈·연결통로에만 남긴다. 기압계 잡음이 1m쯤이라 짧은 구간에서는 뜻이 없고, 실내 계단·엘리베이터는 양 끝이 같은 자리에 그려지기 때문이다.
  - 구간을 그려진 방향과 반대로 걸었으면 읽은 값을 맞바꿔 구간 방향 기준으로 적는다.
  - 기압계가 없는 기기에서는 높이를 남기지 않고, 계단의 오르내림은 사람이 고른다.
- **나침반**: 자력계 x, y로 자북 기준 방향각(0~360°)을 구한다(`headingFromMagnetometer`). 휴대폰을 눕혀 들었을 때만 맞다.
- 측정값은 **현장 기록의 측정값으로만** 남긴다. 지도 원본의 `ext.floor_height_m`이나 길찾기 시간에 자동으로 넣지 않는다(SPEC-v0.2 9장: 경사도 계산·고도 합치기는 하지 않음).

## 4. 현장 기록 파일

`data/schema/survey.schema.json`이 모양을 검사한다. 타입과 함수는 `packages/core/src/survey/`.

```json
{
  "format": "campo-survey",
  "version": 1,
  "id": "sv-20261114-eng1-3f",
  "campus": "hanyang-seoul",
  "surveyed_at": "2026-11-14T10:00:00+09:00",
  "changeset": { "id": "cs-20261114-eng1-3f", "source": "editor", "…": "SPEC-v0.2 7.1과 같은 changeset" },
  "attachments": {
    "n_ENG1_3_door_k7x2qa": { "recorded_at": "…", "photos": ["photos/n_ENG1_3_door_k7x2qa-1.jpg"], "photo_meta": { "photos/n_ENG1_3_door_k7x2qa-1.jpg": { "heading_deg": 87 } }, "heading_mag_deg": 87.5, "pressure_hpa": 1012.3 }
  },
  "vertical": [
    { "edge_id": "e_ENG1_3_k2m9xa", "pressure_start_hpa": 1012.3, "pressure_end_hpa": 1011.8, "height_m": 4.2, "method": "barometer", "measured_at": "…" }
  ]
}
```

- `changeset`: 앱에 실어 둔 캠퍼스 데이터(기준 상태)와 조사 뒤 상태의 차이다. 기존 changeset과 형식이 같아서 충돌 검사(`rev_mismatch` 등)와 `applyChangeset`을 그대로 쓴다. 지도를 바꾸지 않고 사진만 붙였으면 없다.
- `attachments`: Feature id별 사진·방향·기압·메모(`photo_meta`: 사진 경로별 `heading_deg`, 0 이상 360 미만, 선택. 없는 예전 파일도 그대로 읽힌다), 그리고 현장에서 적은 `hours`·`closed_period`·`access_condition`·`sync_group`(선택). 사진 경로는 기록 폴더 안의 `photos/…`만 허용한다.
- `vertical`: 구간별 기압 측정. `height_m`은 구간의 `from`에서 `to`로 올라간 높이이고 내려가면 음수다.
- 누가, 어느 기기로, 어떤 경로로 걸었는지는 필드가 없다. 스키마가 모르는 필드를 모든 단계에서 막는다.
- 되돌린 Feature의 첨부와 측정은 내보낼 때 빠진다(`buildSurvey`).

## 5. 저장과 내보내기

- 앱은 동작 하나마다 기기 안에 현재 상태를 저장한다(임시 파일에 쓴 뒤 바꿔치기). 앱이 꺼져도 이어서 조사한다.
- [데이터 내보내기]는 `survey.json`과 `photos/`를 zip 하나로 묶어 공유한다.
- PC 편집기의 "현장 기록 불러오기"가 zip을 읽어 스키마 검사 → 충돌 검사 → `applyChangeset` 한 번(되돌리기 한 번)으로 넣고, 파일은 `data/surveys/{id}/`에 둔다. `survey.json`은 커밋하고 `photos/`는 커밋하지 않는다(용량, 사람 얼굴).
- **마그넷 스냅(지점 단위)**: 이미 그려진 길을 따라 걸은 기록은 길을 두 번 그리지 않는다. 건물 전체가 아니라 지점마다 판단한다.
  - 실내: 같은 건물·같은 층의 기존 평지 구간에서 2.5m(지름 5m) 안. 바깥: 기존 바깥 구간에서 5m(지름 10m) 안.
  - 양 끝과 중간이 모두 기존 길을 따르는 새 구간은 만들지 않는다. 그 구간·지점의 사진과 높이 측정은 따라 걸은 기존 구간의 상세 정보에 보인다(구간 방향과 반대로 걸었으면 높이 부호를 뒤집어 보여 준다).
  - 반경 안에 기존 길이 없는 구간은 앱에서 기록한 지점·구간 그대로 만든다. 새 길이 기존 길과 닿는 끝 지점은 기존 구간을 나눠 그 위에 놓는다(`splitEdgeAt`). 문·출입구·계단·엘리베이터 지점은 길 위의 지점으로 치지 않는다.
  - 전부 이력 한 줄이다.

## 6. 실행과 구조

- `npm run mobile`이 캠퍼스 데이터를 앱에 싣고(`apps/mobile/scripts/bundle-campus.mjs`, 기본 `hanyang-seoul`, 다른 캠퍼스는 `CAMPO_CAMPUS`) Expo 개발 서버를 띄운다. 휴대폰의 Expo Go로 QR을 읽는다.
- Metro는 저장소 전체를 본다(`metro.config.js`의 `watchFolders`). 앱은 `@campo/core`를 빌드 없이 TypeScript 원본으로 가져온다. React는 앱의 것 하나만 묶이게 고정한다(편집기와 패치 버전이 다르다).
- 화면 밖 로직은 React Native를 가져오지 않는 순수 모듈이고 Vitest(`apps/mobile/test`)로 검사한다: `src/survey`(기록 계획, 조사 세션, 측정값), `src/storage`(기기 저장), `src/export`(zip), `src/sensors/shared.ts`(센서 구독 공유), `src/map/project.ts`(지도 계산).
- 센서는 화면이 앞에 있을 때만 읽는다. 구독은 센서마다 하나를 나눠 쓰고, 읽는 곳이 없어지면 바로 푼다.
- 캠퍼스 데이터가 바뀐 새 앱에서 예전 조사를 이어갈 수 없으면(changeset 충돌) 기록을 지우지 않고 사람에게 묻는다.
