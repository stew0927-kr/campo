# 지도 화면

기존 `useCampusData`, `useCampusRoute`, `useGpsMatcher`를 호출합니다. 계약·코어·실제 지도 파일은 수정하지 않습니다.

- 검색, 지도 임의 점, 등록된 장소 점으로 출발·도착을 선택합니다. 지도 선택 모드에서 초록 점을 누르면 실제 노드로 선택합니다. 실내는 임의 좌표 대신 등록된 지점을 선택해야 합니다.
- 이동 방식 5종을 제공하고 내정보의 기본 보행 방식 변경을 반영합니다. 요청이 바뀌면 오래된 결과를 지웁니다.
- 실외 전체 경로 개요와 실내 건물·층 보기를 제공합니다. 실내 외곽선·연결은 등록된 데이터만 표시하며 층 번호로 경로를 만들지 않습니다.
- 앱 실행 중 장소 즐겨찾기를 공유합니다. 타 탭에서 온 목적지는 실제 노드 존재를 확인한 뒤 선택합니다. 없으면 이름 검색을 열며, 개발용 데이터와 실제 콘텐츠를 혼합하지 않습니다.
- 위치 권한은 사용자가 현재 위치 또는 위치 안내 시작을 눌렀을 때만 요청합니다. 권한이 없으면 수동 길찾기를 사용합니다. 위치 안내는 실외 경로 이탈 시 기존 엔진으로 재탐색하며, 실내는 정확한 지점을 수동 선택합니다. 백그라운드·탭 이탈·중지 시 센서 구독을 해제합니다. 기압계 실패 시 GPS만 사용합니다. 상대 높이만 전달하고 절대 기압·위치 이력을 저장하지 않습니다.
- 사진은 선택적인 `photoCatalog`가 제공될 때 기존 사진 Hook·지도 마커·뷰어를 재사용합니다. 현재 카탈로그는 비어 있어 연결 대기를 안내합니다.
- 실제 데이터는 현재 비어 있습니다. 개발 빌드에서 야외 가상 3지점 또는 기존 core `campus-basic` fixture를 복사한 실내 시험 번들을 선택할 수 있습니다. 실내 시험은 ‘정문 → 가상 408호 선택’ 후 길찾기를 누릅니다. 가상 지리·건물이며 실제 한양대 길이 아닙니다. 이 데이터로 장소 즐겨찾기는 만들지 않습니다.
- Expo Go/웹에서는 네이티브 지도 대신 안내 상자를 보여 줍니다. 웹용 추가 패키지는 설치하지 않았으므로 웹 실행 자체는 이번 환경에서 검증하지 않았습니다.

저장소 루트에서 기존 연결 테스트:

```sh
npx vitest run --config apps/app/src/features/map/vitest.config.mts
```

새 지도·실내·센서·화면·탭 간 전달 테스트는 `apps/app/test/app*.test.ts`에 있고 루트 `npm test`에 포함됩니다. Node 화면 테스트는 네이티브 모듈을 대체한 렌더링 검사이며 실제 터치·지도·센서 E2E 검사가 아닙니다.

Android 개발 앱에서 확인할 것:

1. MapLibre 포함 개발 APK에서 첫 지도·OSM 타일·출처·확대·장소 선택을 확인합니다. 이번 작업에서는 APK를 만들거나 배포하지 않았습니다.
2. 작은 화면·큰 글씨·검색 키보드·모달 닫기를 확인합니다.
3. 위치 권한 거절 후 수동 경로와 다섯 이동 방식, 같은 출발·도착, 캠퍼스 밖 지점을 확인합니다.
4. 실내 시험 번들로 계단 회피·엘리베이터 우선·층 변경 표시를 확인합니다. 실제 데이터가 들어오면 현장 경로를 다시 확인해야 합니다.
5. 실외에서 위치 수신·이탈·재탐색·백그라운드·탭 이동·구독 중단을 확인합니다. 실내 GPS 층 추정은 별도의 현장 검증이 필요합니다.
6. 각 콘텐츠 탭과 즐겨찾기에서 지도 이동·자동 목적지 또는 검색 대체를 확인합니다.
