# 지도 화면

기존 `useCampusData`, `useCampusRoute`, `useGpsMatcher`를 호출합니다. 계약·코어·실제 지도 파일은 수정하지 않습니다.

## 화면 구성 (전체화면 지도)

지도는 하단 탭 위까지 화면 전체를 채우고, 조작은 지도 위에 떠 있는 요소와 하단 시트로 나눕니다.

| 화면 | 위 | 아래(시트) |
|---|---|---|
| 기본 | 둥근 장소 검색바 + 파란 `길찾기` 버튼, `가장 가까운 화장실` 버튼, 개발 빌드에서는 `개발 데이터` 칩. 오른쪽 아래 `건물에서 층 고르기` 토글(건물 모양)과 `내 위치로 이동` | 데이터 상태 안내, 실외 지도 또는 `건물 · 층`, `건물 목록`/`건물 바꾸기`, 층 칩, `실외 지도로 나가기`, 이 보기의 장소 목록 |
| 장소 선택 | 왼쪽 위 `←`(선택 취소) + 고른 장소 이름·위치(누르면 다시 검색) | 선택한 장소 카드(출발지로·도착지로·즐겨찾기)와 기본 화면 내용 |
| 장소 검색(반화면) | 없음(위쪽 절반은 지도) | `←` · 제목 · `⌃`/`⌄` · 검색어 · (출발·도착·화장실) `현재 위치`/`지도에서 선택` · 결과 또는 건물→층→시설 목록 |
| 출발·도착 입력 | 출발/도착 입력란, ↑↓ 바꾸기, ✕ 닫기(선택 초기화) | 이동 방식 5종, `길찾기` |
| 경로 결과 | 뒤로(입력 수정) + 출발→도착 요약 | `휠체어 가능` 스위치, 이동 방식 5종(누르면 즉시 재계산), 시간·거리·계단·층 이동, 왕복 보기, 위치 안내 시작/중지, `로드뷰로 보기`, 실내 층 보기, 단계별 안내(사진 있는 단계는 눌러서 지도 말풍선) |
| 지도에서 선택 | 없음(지도 전체 사용) | 안내 문구와 `지도 선택 취소` |

### 장소 선택과 뒤로가기

검색이나 지도에서 장소를 고르면 위쪽 검색바 자리에 `←`(`선택 취소`, 48pt)와 장소 이름이 뜹니다. `←`는 선택을 바로 풀고, 그 선택이 **검색어로 찾은 것**이면 같은 검색어로 검색 시트를 다시 엽니다(한 번 더 뒤로 → 기본 지도). 지도에서 누른 장소·목록에서 고른 장소·검색어 없이 고른 장소는 바로 기본 지도로 돌아갑니다. 안드로이드 뒤로가기도 같은 순서입니다.

### 배율별 실내 아이콘·이름표 (`mapLabels.ts`)

| 배율 | 실내(건물·층 보기) | 실외 |
|---|---|---|
| `zoom < 18` (넓게) | 복도 선 + 시설 아이콘만(아이콘 간격 12px) | 장소 점만 |
| `18 ≤ zoom < 19.5` (중간) | 시설 아이콘만(간격 6px), 좌표 가운데에 놓음 | 장소 점 + `zoom ≥ 18`부터 이름표 |
| `zoom ≥ 19.5` (확대) | 아이콘 + 이름표(겹침 방지, 최대 16개) | 이름표(겹침 방지) |

- 시설 아이콘은 그래프의 `node_type`에서 뽑습니다(`floorFacilityNodes`): 문=강의실, `elevator_stop`=엘리베이터, `stair_landing`=계단, `restroom`=화장실, `entrance`=출입구. 계단·엘리베이터는 이름이 없어 `places`에 없기 때문입니다. 아이콘은 흰 원 + 얇은 테두리, 색은 `theme.facility`(모두 흰 바탕 대비 4.5:1 이상).
- 겹침 방지(`declutter`): 화면 가운데 기준 픽셀 좌표(위도별 미터/픽셀 근사, 지도 회전 반영)로 우선순위 높은 것부터 배치합니다. 출발/도착 > 선택한 장소 > 경로가 지나는 지점 > 화장실·엘리베이터·계단·출입구 > 강의실·일반 지점. 이름표끼리 10px, 아이콘과 6px 이상 떨어져야 하고, 화면 밖은 그리지 않습니다.
- 이름표: 흰 바탕·8px 둥근 모서리·1px 테두리·옅은 그림자, 12px/600, 최대 폭 132px 한 줄 말줄임, 왼쪽에 시설 색 점. 출발·도착·선택은 초록·빨강·파랑 바탕. 점 위쪽에 띄워 복도 선을 가리지 않습니다. 실내의 작은 회색 점은 아이콘이 빠진 장소도 누를 수 있게 남겨 둔 것입니다.

### 마커·이름표 배치 성능

규칙(우선순위·간격·`MAX_ICONS` 48·`MAX_LABELS` 16·배율 단계)은 그대로이고, 같은 화면이면 결과도 이전 구현과 똑같습니다(`test/appMapPerf.test.ts`가 이전 구현을 그대로 옮긴 비교 기준과 대조).

- `floorFacilityNodes`: 그래프마다 한 번 건물·층별로 색인하고, 층을 바꿀 때는 그 층 목록만 복사합니다.
- `declutter`: 마커 목록마다 한 번 배치 순서(우선순위)와 경위도 격자를 만들고(같은 배열이면 재사용), 화면을 덮는 칸의 마커만 투영합니다. 아이콘이 다 차면 강조 표식이 아닌 나머지는 투영하지 않고, 겹침은 화면 px 격자로 근처 상자끼리만 비교합니다.
- `DeclutterScheduler`: 이동 중(`onRegionIsChanging`)에는 80ms 간격·이동 임계값을 넘을 때만 다시 배치하고, 멈춤(`onRegionDidChange`)·화면 크기·마커/단계 변경 때는 바로 정확히 배치합니다. 배치가 같으면 이전 배열을 그대로 돌려줘 다시 그리지 않습니다.
- `CampusMap`: 화면 좌표는 ref에 두고 배치가 바뀔 때만 다시 그립니다. 아이콘·이름표는 마커 객체 기준 `memo` 컴포넌트, `onPlace`는 ref로 고정해 부모가 다시 그려도 마커를 다시 만들지 않습니다.
- 실제 `CampusMap`을 가짜 MapLibre 위에서 돌려 렌더 횟수를 재는 검사는 `test/uiHarness/campusMap.html`(uiHarness의 `CampusMap markers` 시나리오)입니다. 네이티브 마커 뷰·제스처 비용은 실기기에서 확인해야 합니다.

### 건물에서 층 고르기

- 오른쪽 아래 건물 모양 토글(`accessibilityRole="switch"`)을 켜면 **실내 매핑 건물**(장소가 1곳 이상, `buildings.ts`의 `mappedBuildings`)만 파란 반투명 면 + 2px 테두리로 강조합니다. 지도에서 강조 건물을 누르면(GeoJSON `onPress`, 장소 점·지도 탭으로 전파되지 않음) 지도 위 층 카드가 뜹니다: 건물명, `B1`·`1F`… 칩(지금 보는 층 표시), `✕`, `지도에서 계속 보기`. 층을 고르면 그 건물·층 실내 보기로 들어가고, 층이 하나뿐이면 바로 들어갑니다. 실내에서도 다른 강조 건물을 눌러 건물을 바꿀 수 있습니다.
- 토글을 끄면 층 카드를 닫고 실외 지도로 돌아갑니다. 실내 보기 중에는 토글이 켜진 상태로 보입니다.
- 이전의 `실외 | 실내` 세그먼트와 가로 스크롤 건물 목록은 없앴습니다. 대신 하단 시트에 `건물 목록`/`건물 바꾸기`(세로 목록 → 층 카드), 현재 건물의 층 칩, `실외 지도로 나가기`를 남겨 스크린리더·발견성을 유지합니다.

### 길찾기 표시 보강 (경로 연결선·경사 구간·실외 기본·나침반)

- **연결 점선**: 지도에서 찍은 점(`nodeType` `point`/`gps`)이 출발·도착이면 경로선은 가장 가까운 걷는 길의 발(foot)에서 시작·끝납니다. 실외 지도에서 핀과 경로선 끝이 1.5m 이상 떨어지면 은은한 파란 점선(폭 3px·불투명도 0.65)으로 잇습니다. 본 경로선 아래 레이어이며 핀은 그대로입니다(`model.ts` `routeConnectors`).
- **경사 구간 카드**: 경사 경고는 계약대로 구간(edge)마다 오고, 각 경고에 경로선 자리(`polylineRange`)와 잘라 낸 좌표(`coordinates`)가 붙습니다. 화면은 `route/slopeSections.ts`의 `slopeSections`로 경로상 바로 이어지고 등급·방향이 같은 경고를 카드 한 장으로 묶습니다(예: `급경사 구간 (내리막 · 최대 12.6% · 약 45m) · 경사가 급한 길입니다`). 카드를 누르면 그 구간으로 카메라가 맞춰 이동하고 주황 `#E68A00`(7px, 흰 테두리)으로 강조, 다른 카드는 교체, 같은 카드는 해제합니다.
- **길찾기는 실외 지도에서**: 출발·도착을 정하면(`choose`, 다른 탭에서 온 목적지, 개발 예시) 실외 지도로 돌아가 어디든 찍을 수 있습니다. 실내는 사용자가 건물 토글·층을 직접 고를 때만 열립니다(실내 호실은 그대로 경로 끝점). 기본 화면의 장소 검색(둘러보기)은 예전처럼 호실의 층을 보여 주고, 그 장소를 `출발지로`/`도착지로` 고르는 순간 실외 지도로 돌아갑니다. 실내 보기 중에는 그 건물 외곽선 바깥을 검정 0.35 막으로 덮고, 바깥을 누르면 `실외 지도로 나가기` 안내를 보여 줍니다(시트에도 같은 단추).
- **나침반**: 왼쪽 아래 출처 표시 위 44pt 버튼. 지도 회전을 따라 바늘이 돌고(회전·기울임 중에는 파란 테두리, 정북이면 회색), 누르면 400ms 동안 정북·기울임 0으로 돌아갑니다(`model.ts` `compassState`). 바늘 상태는 나침반 컴포넌트에만 있어 지도 전체를 다시 그리지 않습니다.

### 반화면 장소 검색

- 장소·출발지·목적지·화장실 검색은 모두 하단 시트(지도 화면의 약 52%, 끌어 올리면 약 88%)로 열리고 위쪽에는 지도가 계속 보입니다(전체 화면 배경 없음, 지도 이동·확대 가능). 시트 밖 지도를 눌러도 검색은 닫히지 않습니다.
- 끝까지 끌어 내리기, `←`, `⌄`(검색 접기), 안드로이드 뒤로가기로 검색을 끝냅니다. 높이는 `sheetModel.ts`의 `searchSheetHeights`.
- 건물·층 목록에서 건물을 열면 지도가 그 건물로 바로 이동하고(카메라 `easeTo`, 외곽선 꼭짓점 평균 또는 장소 평균) 시트는 층 목록으로 내려갑니다. 검색을 닫아도 카메라는 그 건물에 머물고 선택은 만들지 않으며, 그 건물은 점선 테두리로 남습니다.
- 웹/Expo Go에서는 지도만 안내 상자로 바뀌고 검색 시트는 그대로 동작합니다.

### 하단 시트

모든 화면의 시트는 핸들 줄을 위아래로 끌거나 누르거나, 오른쪽 `⌃`(크게 펼치기)·`⌄`(접기) 버튼으로 **펼침 / 기본 / 접힘** 세 상태를 오갑니다. 접힘에서는 핸들과 미니 바(경로 화면은 `12분 · 340m`)만 남고 지도가 화면을 채웁니다. 높이 계산은 `sheetModel.ts`(순수 함수)입니다.

### 가장 가까운 화장실

`가장 가까운 화장실` → 검색 화면에서 출발 위치를 `현재 위치` / `지도에서 선택` / 검색·건물 목록 중 하나로 고르면, `restroom.ts`가 코어 `findNearestRestroom`(지도 위 점은 `findNearestRestroomFrom`)으로 화장실을 정하고 기존 `useCampusRoute`로 경로를 바로 띄웁니다. `휠체어 가능`을 켜면 휠체어 사용 가능(`wheelchair: 'yes'`) 화장실만, `wheelchair` 방식으로 즉시 다시 찾습니다. 일반 길찾기에서도 같은 스위치가 `wheelchair` 방식을 켜고 끕니다.

### 계층 검색

검색어가 비어 있으면 건물(장소 많은 순, 마지막에 `야외 장소`) → 층 → 시설(화장실·강의실·출입구·기타) 순서로 내려가며 고릅니다(`placeTree.ts`). 검색어를 입력하면 기존처럼 평평한 결과 목록입니다.

### 캠퍼스 로드뷰

- 지도에서 초록 사진 지점(기본 화면) 또는 경로의 사진 단계(경로 화면, 같은 지점을 두 번 지나면 보라 점)를 누르면 썸네일 말풍선이 뜨고, 말풍선을 누르면 분할 로드뷰가 열립니다. 두 번 지나는 지점은 말풍선에서 `가는 길 · n단계` / `오는 길 · n단계`를 고릅니다.
- 분할 로드뷰(`RoadviewScreen.tsx`): 위 55%에 사진·진행 방향 화살표·이전/다음·`이 지점 다른 방향 사진`·전체화면 `↗↙`, 아래에 미니 지도(현재 지점 + 사진 `heading_deg`·`hfov_deg` 시야각 부채꼴, 다른 방향을 고르면 바로 회전)와 정보 카드(지점 이름, 실내/실외·층, 바라보는 방위, 단계 문구). Expo Go·웹은 미니 지도 대신 같은 부채꼴의 나침반을 그립니다.
- 사진 고르기·화살표는 기존 `photos/routePhotos.ts`·`viewerModel.ts`(코어 `choosePhotoForStep`·`photosForPoint`·`arrowFor`)를 그대로 쓰고, 장면·부채꼴·마커 묶음·왕복 잇기는 `photos/roadviewModel.ts`(순수 함수)입니다.
- 개발 메뉴 `실내·실외 로드뷰 시험`: `roadviewDemo.ts`의 가상 캠퍼스(정문·갈림길·광장 ↔ 가상 공학관 출입구 ↔ 1층 로비·계단·엘리베이터·화장실, 2층 복도·201호·화장실)와 지점별 2~4방향 SVG 가상 사진(`photos/demoPhotoArt.ts`, 네트워크 불필요)을 씁니다. 예시 버튼: 정문 → 201호, 왕복(정문 ↔ 본관 앞), 갈림길(정문 → 광장). 실제 한양대 길·사진이 아니며 data/·서버 사진과 섞지 않습니다.

- 우측 하단 `내 위치로 이동` 버튼은 누를 때만 위치 권한을 요청하고, 받은 좌표로 카메라를 옮기며 내 위치 점을 표시합니다.
- 입력란을 누르면 검색 화면이 열리고 `현재 위치`·`지도에서 선택`·검색 목록 중에서 고릅니다. 출발·도착이 모두 정해지면 바로 경로를 계산합니다. 다른 탭에서 넘어온 목적지는 기존처럼 사용자가 `길찾기`를 눌러 확인합니다.
- 검색바에서 고른 장소는 카메라를 그 위치로 옮기고(`MapProps.focus`), 하단 카드에서 출발지·도착지로 지정합니다.
- 안드로이드 뒤로가기: 로드뷰 → 지도 말풍선 → 검색 → 개발 메뉴 → 층 카드 → 지도 선택 → 경로 결과 → 입력 화면 → 선택 장소(→ 그 검색) 순서로 닫습니다.

- 검색, 지도 임의 점, 등록된 장소 점으로 출발·도착을 선택합니다. 지도 선택 모드에서 초록 점을 누르면 실제 노드로 선택합니다. 실내는 임의 좌표 대신 등록된 지점을 선택해야 합니다.
- 이동 방식 5종을 제공하고 내정보의 기본 보행 방식 변경을 반영합니다. 요청이 바뀌면 오래된 결과를 지웁니다.
- 실외 전체 경로 개요와 실내 건물·층 보기를 제공합니다. 실내 외곽선·연결은 등록된 데이터만 표시하며 층 번호로 경로를 만들지 않습니다.
- 앱 실행 중 장소 즐겨찾기를 공유합니다. 타 탭에서 온 목적지는 실제 노드 존재를 확인한 뒤 선택합니다. 없으면 이름 검색을 열며, 개발용 데이터와 실제 콘텐츠를 혼합하지 않습니다.
- 위치 권한은 사용자가 현재 위치 또는 위치 안내 시작을 눌렀을 때만 요청합니다. 권한이 없으면 수동 길찾기를 사용합니다. 위치 안내는 실외 경로 이탈 시 기존 엔진으로 재탐색하며, 실내는 정확한 지점을 수동 선택합니다. 백그라운드·탭 이탈·중지 시 센서 구독을 해제합니다. 기압계 실패 시 GPS만 사용합니다. 상대 높이만 전달하고 절대 기압·위치 이력을 저장하지 않습니다.
- 사진은 선택적인 `photoCatalog`(서버 공개 사진)가 제공될 때 기존 사진 Hook으로 고르고 로드뷰로 보여 줍니다. 가상 데이터에서는 로드뷰 시험 캠퍼스에만 가상 사진을 연결합니다.
- 실제 데이터는 현재 비어 있습니다. 개발 빌드에서 야외 가상 3지점 또는 기존 core `campus-basic` fixture를 복사한 실내 시험 번들을 선택할 수 있습니다. 실내 시험은 ‘정문 → 가상 408호 선택’ 후 길찾기를 누릅니다. 가상 지리·건물이며 실제 한양대 길이 아닙니다. 이 데이터로 장소 즐겨찾기는 만들지 않습니다.
- Expo Go/웹에서는 네이티브 지도 대신 안내 상자를 보여 줍니다. 웹용 추가 패키지는 설치하지 않았으므로 웹 실행 자체는 이번 환경에서 검증하지 않았습니다.
